## Usage

Icon buttons represent an action with an icon instead of a visible text label. Choose a familiar icon whose meaning is clear in context. Otherwise, use a [button](/components/Button) with a visible text label.

Every icon button displays a tooltip on hover and keyboard focus. The tooltip repeats the accessible label by default, helping users confirm the action before activating it.

## Labels

Every icon button needs a concise name that describes what happens when someone activates it. Begin with a clear verb when possible, such as Search, Share, Close, or Delete item.

Describe the action rather than the icon's appearance. Keep supplementary tooltip text short and non-essential.

## Hierarchy and emphasis

Use the default treatment for most icon buttons. Use stronger emphasis only for the highest-priority action in a group, and quieter treatment for familiar secondary actions in compact interfaces.

Reserve danger styling for destructive actions. The icon and accessible name must still communicate the destructive outcome without relying on color alone.

Use the borderless treatment only when the surrounding interface already provides enough structure and the control remains discoverable in every interaction state.

## Shape

Use the standard shape for general actions. Use a circular shape only when it matches an established interaction pattern, such as sending a chat message or advancing through media.

Keep shape consistent among related controls. Do not use shape alone to communicate an action's meaning or state.

## Unavailable actions

Remove an unavailable action when it is not useful to the current task. When it must remain visible, choose its behavior based on whether people need an explanation.

Keep the control focusable and responsive when activating it can explain why the action is unavailable or help resolve the condition. Provide persistent page-level messaging when the limitation affects a larger workflow.

Use a fully disabled control only when it should not receive focus or respond to input. Disabled controls do not display a tooltip, so essential explanations must remain visible elsewhere.

## Loading

Show progress in place when an action takes time to complete. Keep focus on the control, prevent repeated activation, and announce that work is in progress. Use a specific announcement when the surrounding context does not make the operation clear.

## Accessibility

- Give every icon button an accessible name, even when the icon seems self-explanatory.
- Ensure the name describes the action and remains accurate when the button's state changes.
- Keep the tooltip available on both pointer hover and keyboard focus.
- Ensure the control has a visible focus indicator.
- Maintain at least a 24 by 24 CSS pixel target size and provide enough spacing from nearby controls.
- Treat the icon as decorative because the accessible name communicates the purpose.
- Do not rely on color, shape, or iconography alone to communicate state.
